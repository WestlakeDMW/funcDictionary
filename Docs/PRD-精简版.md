## 1. 产品概述

funcDictionary 是一个按项目组织的共享功能词典，让用户与不同 Agent 使用同一套自然语言称呼来定位代码，并随着代码变化持续更新。

核心价值是保存“这个功能怎么称呼、在哪里实现、被哪里使用、后来如何变化”的共同理解。

用户主要在 App 中查找和理解功能、查看调用位置与变化历史、补充自己的叫法和说明。

Agent 阅读代码与已有词典，沿用项目中已有的自然语言定义，完成代码修改时同步维护受影响的词条。

App 保存词典，提供查询、浏览和人工补充入口，接收 Agent 更新，并向不同 Agent 提供同一份最新数据。同一项目内共享定义，项目数据仍各自独立。

主要场景：描述功能找到函数；查看函数被哪些功能和位置调用；换一个 Agent 继续开发；代码改名或移动后通过旧叫法重新定位。使用体验应当直接、可理解，日常维护尽量自动完成。

## 2. 版本分期与功能取舍

本轮 MVP 聚焦 macOS 本地使用，完成“建立词典 → 查找功能 → 查看调用与历史 → 随开发自动更新”。

| 原有能力 | 精简方案 |
| --- | --- |
| 项目创建、选择工作区、关联仓库 | 合并为“添加项目”，选择源码目录后创建或复用项目 |
| 自然语言、函数名、旧名与别名搜索 | 保留为一个搜索入口 |
| 通用关系列表、组成与层级 | 优先整理成“在哪里实现”和“被哪里使用”；保留有证据的功能位置描述 |
| 模糊词、人工备注、精准说法、多个复制入口 | 合并为“其他叫法与说明”和一个“复制定位信息”动作 |
| 实现历史、名称与位置变化 | 保留为按需展开的“变更记录” |
| 标记已审核、Proposal、Change Request | 取消常态审批流程；仅身份不确定或实质内容冲突时请求处理 |
| Important / Critical 分级与保护传播 | 取消等级和传播机制；重要性判断并入人工说明，已有内容保留 |
| 生命周期、热度、Active Context 评分 | 移出本轮 MVP，不作为搜索排序和详情展示的依赖 |
| Cluster、主分组和分组审批 | 移出本轮 MVP，使用搜索及已有文件、模块信息定位 |
| UI 控制参数、通用属性大表、截图与截图里程碑 | 移出本轮 MVP；功能的位置用简短文字和代码依据表达 |
| Harness 中心、多 CLI 控制台、从 App 启动或发送任务 | 移出日常主流程；本轮接入入口只提供一次性协作指引，使用用户已有 Agent 会话 |
| 手动导入增量、导出词典、修复与诊断信息 | 自动交换承担日常维护，必要维护工具收在设置或异常详情 |
| Collection Score 收录评分 | 取消；按选定的一方源码范围盘点函数、方法和重载 |

iOS、iPadOS、Mac Catalyst、CloudKit 跨设备同步继续暂缓。多人权限、通用聊天、IDE 深度插件、复杂调用图和额外后台常驻服务不纳入本轮。

## 3. 信息架构与导航

主窗口围绕项目列表、搜索结果、词条详情展开。单项目直接进入该项目词典，多项目从侧栏切换。设置放在系统设置入口。

列表只展示中文名称、简短用途、对应函数和所在文件。默认不展示评分、审核等级、生命周期或协议字段。

详情先展示“做什么、在哪里”，再按需展开“被哪里使用”和“变更记录”。输入输出、副作用、其他叫法与人工说明按内容展示，无内容的辅助区块隐藏。

主要动作只保留“打开源码”“复制定位信息”“编辑说明”。复制内容包含统一叫法、稳定标识、当前函数和代码位置，方便人或 Agent 继续定位。

项目顶部显示简短更新状态与最后更新时间；错误的原因和处理方式在需要时展开。函数名和代码路径可以使用代码形式，普通状态与动作使用中文。

## 4. 核心功能模块

### 4.1 添加项目与建立词典

用户选择源码目录，App 创建或复用项目、准备交换资料，并提供“复制接入说明”。用户将指引交给正在使用的 Agent，完成一次性接入。

接入需要把维护约定接到该 Agent 实际读取的规则入口，使用 Skill 或项目协作规范，并保留已有项目规则。只导出一份未被读取的说明文件不算接入完成。

Agent 首次盘点选定的一方源码中的函数、方法和重载，排除第三方依赖、生成物和无关文件，分批建立词条。未完成的范围清楚记录，不要求用户逐条审核后才能使用。

验收：重复添加保留项目和词条；首次接入后可查询实际入库内容；部分完成与全部完成有明确区别。

### 4.2 找到功能与当前代码

一个搜索框接受自然语言、函数名、旧名、文件和模块信息。优先沿用用户已有叫法；结果附简短匹配依据，有歧义时展示候选。

功能位置描述，例如“右上角的同步按钮”，可以作为叫法或使用场景记录，不要求建立单独的界面属性系统。

验收：同一词条可通过中文描述和函数名命中；代码改名、移动后旧叫法仍能找到当前实现。

### 4.3 查看调用位置与变化历史

“被哪里使用”优先展示直接调用方：调用方名称、对应功能或使用场景、调用函数及准确文件位置，并可打开相应源码。

同一函数在多个位置被调用时分别列出。调用位置与函数定义位置分别保存。有代码证据的页面、流程归属可以一并展示。

间接调用必须标明路径和依据，MVP 不要求全仓库多层图谱。尚未扫描、动态调用或无法确认的部分标为未确认；没有调用记录不能直接解释为无人使用。

变更记录用简短时间线说明函数改名、移动、拆分、合并、移除和重要行为变化，并保留旧称与去向。用户主要查看结果，不需要为每次变化执行审批操作。

验收：使用一个有两个直接调用位置的函数验证列表与跳转；一次改名和一次移动后，旧称、当前位置与历史一致。

### 4.4 多 Agent 共享与自动维护

不同 Agent 读取同一个项目词典，以稳定标识关联代码，沿用已有自然语言名称、人工别名和说明。新增 AI 解释保留来源，不覆盖人工内容。

受支持 Agent 的任务流程为：开始时读取词典 → 修改代码 → 更新受影响词条及调用记录 → 校验并提交 → 检查入库结果。词典维护作为编程任务的固定收尾步骤，正常情况下用户无需再次下达同步指令。

普通事实更新自动入库。代码结构已经发生变化时，词典记录变化结果；身份去向无法确定、人工说明与新事实冲突或并发修改无法合并时，保留最后可信内容，只对受影响项提示处理。

App 运行时自动处理已接入且可访问项目的更新，不依赖当前查看哪个项目。App 退出时增量保留待处理，下次启动补入；等待入库不能显示为已经同步。

写入版本过期时，Agent 重新读取并计算变化；多个 Agent 的提交按版本协调，避免互相覆盖。

验收：Agent A 写入后，Agent B 能读取同一标识和叫法；一次常规代码修改无需人工导入或审批即可在 App 中出现；切换项目和退出后恢复均不丢失待处理更新。

## 5. 关键交互合同

首次使用：添加项目 → 复制接入说明 → 由已有 Agent 建立词典 → 查看结果。

日常使用：输入描述 → 查看用途和位置 → 查看调用或打开源码。人工说明直接编辑保存。

项目状态限于“正在建立/更新”“已更新”“等待入库”“需要处理”；最后更新时间一直可查。尚未完成的扫描在状态详情中说明范围。“已更新”以 App 入库并刷新共享读取数据为准。

有不确定身份或内容冲突时，在对应词条展示一次“需要处理”提示，说明旧内容、新内容及原因；用户选择或修正后继续。不建立独立审批中心。

使用系统点击、键盘选择和滚动，无新增复杂手势。列表更新时保留当前选择与阅读位置，动效遵循系统默认并支持减弱动态效果。

## 6. 数据模型与领域不变量

MVP 以函数、方法和重载为基础词条，使用中文名称和说明表达功能，一个功能描述可以匹配多个相关函数；同一函数被多处使用时保留多个调用记录，不复制词条。

核心数据包括：项目、稳定词条标识、统一叫法与别名、功能说明、当前代码位置、调用记录与依据、人工备注及重要性判断、变化历史、来源和更新版本。

重命名和移动保持身份连续，重载分别识别。删除的函数留下历史记录，确认的拆分、合并记录去向。无法确定身份时不强行合并或重用旧标识。

人工措辞与代码事实分别保存。保留用户叫法，不以人工旧说明覆盖已变化的代码事实；存在冲突时明确提示。

调用记录至少能区分调用方、被调用方、调用位置和证据来源。调用关系变化与函数本身变化都进入历史。

各项目独立保存；项目内部不同 Agent 共用同一份词典。版本校验、重复提交去重和写入失败恢复由底层负责。

既有词条、人工内容、历史及未处理的旧治理记录需要兼容保留。精简界面不等于清空数据；旧待审批内容不自动转为已批准，新流程不继续依赖已撤下的常态审批入口。

## 7. 设计规范

沿用原生 macOS 布局、系统字体、语义颜色、SF Symbols 和标准控件。内容以文字与列表为主，减少装饰、标签和重复按钮。

详情第一屏回答“是什么、在哪里”，关联信息逐步展开。长路径和函数签名可以完整查看与复制，窗口缩放时保持可读。

支持键盘完成搜索、选择和主要操作，提供 VoiceOver 名称；支持深色模式、增强对比度和减弱动态效果。状态不只依赖颜色。

## 8. 技术约束

继续使用 macOS SwiftUI、Core Data 和已有结构化文件交换能力，不为本次收敛引入新的数据库、向量检索或常驻服务。

普通同步无需人工操作；底层仍校验项目、版本、身份和完整性，采用原子写入与失败恢复。撤下审批入口时，需要同步调整协议、校验和写入规则，不能只隐藏按钮后留下无法完成的流程。

Skill 或协作规范负责 Agent 的约定，实际触发与收尾检查必须对明确支持的 Agent 验证。仅凭存在说明文件，不能宣称所有 Agent 都会自动更新。用户直接手改源码的补更新方式不计入本轮自动维护承诺。

自动入库范围为 App 运行期间；退出期间可靠排队，重新运行后补入。Agent 读取数据时能识别当前版本与待入库状态。

沿用 5,000 条词条的搜索参考集与 p95 小于 150 ms 的性能目标，发布时记录设备和测量条件。

## 10. 本轮建议与待补充边界

本稿按“只保留核心用途”提出三项范围裁决：取消日常审批，只处理真实歧义；MVP 以函数为基础，取消价值评分筛选；Agent 接入使用已有会话，App 内任务控制台暂缓。

具体支持哪些 Agent、如何在每一种 Agent 中触发规则读取和任务收尾，需要在实现前列清并完成真实验证；文档仍以现有 Codex、Hermes 接入基础为参考，不承诺任意 Agent 无配置接入。

## 11. 验证与发布门槛

1. 从添加真实项目到查询入库词条，不需要用户理解增量协议、进入连接器控制台或逐条审核。
2. 中文叫法与代码名称可找到同一条目，旧叫法在重命名、移动后仍有效。
3. 直接调用方、所在功能和调用位置有可复核依据；未确认范围明确标示。
4. 使用两个真实 Agent 交接同一个项目，第二个能读取第一个写入的定义、标识与最新版本，人工内容保留。
5. 真实 Agent 一次普通代码修改后，词条与调用记录自动入库；用户无需重新提醒或手动导入。
6. App 查看其他项目时，已关联项目仍可更新；App 退出期间的提交可以在重启后补入，状态准确。
7. 普通修改不触发逐条审批；身份不确定或人工内容冲突有清楚的处理入口；旧数据和历史完整保留。
8. 构建、关键测试、实际运行、键盘与可访问性、搜索性能分别验证；历史测试结果不替代本稿验收。

Review loop 遵循项目规则：BLOCKER = 0、MAJOR = 0、Build = PASS、关键验收标准 = PASS 后停止；MINOR / NOTE 记录，不自动扩展修改。
